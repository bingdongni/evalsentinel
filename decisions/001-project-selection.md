# 001 — 确定 EvalSentinel 的方向与首版范围

日期：2026-11-12。状态：**独立项目已确定，进入首版开发准备**。

本决定替代此前“等更多案例再决定是否独立立项”的安排。项目目标现在确定；
具体功能是否进入首版，继续按证据和维护成本取舍。当前还没有发布软件包，
不得把下文的目标写成已经实现的能力。

## 一句话定位

**EvalSentinel 是有状态智能体评测器的离线反例测试工具：用有明确真值的行为
序列，检查原生评测器是否误通过不完整、越权或证据不足的执行，并产出可供
上游接纳的最小回归用例。**

首批用户是维护 Agent / MCP 集成测试、安全断言和评测判定器的开发者。
输入为版本固定的原生实现、声明的行为要求和已知答案用例；输出保留原生
判定、检查标识、适用范围、实际执行状态和可复现命令。模型 API 调用预算为 0，
不需要 GPU。低内存和耗时上限属于待实测的工程目标。

## 已有依据与边界

1. **MCP 已实测并已贡献。**
   [conformance #583](https://github.com/modelcontextprotocol/conformance/pull/583)
   已以 `bingdongni` 提交，commit
   `c69c46dbef3083ab4e87b06a6b0e066cc487e214`，基线
   `96a6f9478b7f2e125cf0360a213383cf57533893`。
   两版协议共 16 次 CLI 对照符合预期，49 个文件、659 项测试通过。
   对照发现本地初版检查器会放过“篡改游标后重试成功”，补充红测并修复了它。
   这是一个已投稿、未合并的上游场景，不能写成正式发行版已经内置的能力。
2. **第二套原生代码可以离线调用。**
   OWASP Harness 固定在
   `970158c10b7e36ae00f12de4ba2a41ca61acabca`，使用其实际的
   `validate_scenario_data`、`Trace.from_dict` 和
   `evaluate_approval_required` 运行了 8 例，没有改写这些函数。
   一次审批覆盖两次调用、参数替换、绑定参数不匹配的输入，在所声明的
   单次审批策略下应拒绝，而该版本返回 pass。正常的一次审批一次调用、
   两次审批两次调用均返回 pass；缺审批和不可信审批返回 fail；没有动作时
   返回 not_run。
   [原始结果](evidence/owasp-native-probe.json)与
   [复现脚本](../decisions/probe_owasp_native.py)保留在本地项目中。
3. **这不是新的 OWASP 漏洞发现。**
   [issue #210](https://github.com/OWASP/Agent-Security-Regression-Harness/issues/210)
   已提出单次审批策略，且已有
   [修复 PR #211](https://github.com/OWASP/Agent-Security-Regression-Harness/pull/211)。
   当前主分支注释明确写着 MVP 下一个有效审批覆盖所有调用。因此本项目把它
   作为已公开的策略差异和回归来源，保留原作者署名；额外声明的策略不能自动
   升格为原实现违反自身契约，更不能据此断言生产漏洞。
4. **有些事实确实不可观察。**
   当前 OWASP Trace 只有 messages、tool_calls、events，未定义统一的调用与
   审批时间线，也没有终态快照契约。不能靠列表位置猜测审批先后，不能把工具
   调用记录当成真实副作用完成的证明。相关性质应报告缺证据或 unsupported。

## 首版 v0.1 的边界

| 内容 | 首版交付与验收 |
| --- | --- |
| MCP 分页契约 | 原样传递游标、空字符串和空页续页、结束本次遍历；保留 MUST / SHOULD 原始级别；完成后的重新发现为有效正对照 |
| 单次审批绑定契约 | 在明确声明该策略时验证审批消费、调用 / 参数绑定；正常重复授权为正对照；不从未定义字段推断时间顺序 |
| 状态证据资格检查 | 当要求“真实完成 / 一次性副作用”却没有所需终态证据时，明确报告不可判定；首版不承诺验证任意外部系统的真实副作用 |
| 原生适配 | MCP 使用原有 CLI；OWASP 使用原有 Python 判定函数。记录完整 pin、来源和适用能力；不把重写的判定器当作第二套独立实现 |
| 回归用例 | 目标至少 30 个已知答案用例，明确标注正、反、缺证据与未执行；按来源和缺陷机制报告，协议版本重复运行不算新的独立案例 |
| 结果与复现 | 机器可读结果、逐例证据、适用性表和原生复现命令；给出维护者可直接导入上游的 fixture / 回归测试 |

v0.1 的目标是两类原生行为契约，加一层证据资格检查；不能把第三行计为
又发现了一个独立缺陷家族。当前已经完成的原生实验是立项依据，不等于
上述 30 例和两个可安装适配器已经交付。

首版开发以 Python 3.12+ 作为轻量控制层；Node 仅用于 MCP 的原生工具链。
采用原生依赖和 CLI，不先建立统一 Agent 运行框架。不训练模型，不要求
LLM judge，不运行真实资金、删除操作或外部写入动作。开发与 CI 均使用
合成的无害字段和本地 fixture。

| 已有工作 | 已核查范围 | 对本项目的约束 |
| --- | --- | --- |
| [evalmut](https://github.com/egnaro9/evalmut) | pin `bc1f770336386e3957579eddd5e79dc386daced7` 的 README、EvalCase、outcome 源码 | 已有好坏变异、适用性拒绝、轨迹计划与 verdict-channel 处理。不能声称“测试评测器”“缺证据不计分”或“支持轨迹”是原创；要验证本项目的原生集成和多步状态案例是否增加实质覆盖 |

| [InfernoSIM](https://github.com/pranaysparihar/InfernoSIM) | 前次调研的 README 和能力说明 | 已有故障回放、缩减和 CI。本项目首版不重做这些系统 |

| [Oracle integrity audit](https://arxiv.org/abs/2610.16067v2) / [EIO-Agents](https://arxiv.org/abs/2610.07675v1) | 论文摘要，未声称完整复现 | 状态完整性、证据契约和可移植记录已有研究；本项目不再发明通用语义标准，先做具体原生集成与可执行回归 |

**待验证的差异假设：**针对分页链、单次授权与状态证据边界，维护一个带
规范来源和良性对照的案例集，并直接测试固定版本的原生实现，能够以较低
集成成本补齐现有工具尚未覆盖的语义问题。这个假设不是已经证明的研究创新。

最快的反证是把相同案例交给 evalmut 的既有接口以及两套上游自身的测试，
比较新增检出、误拒与适配工作量。若现有引擎可以完成这些工作，复用引擎，
让本项目聚焦有状态案例与原生适配包；没有必要为了独立仓库再造重复代码。

## 完成门槛、衡量方式与近期交付

v0.1 的完成标准是：一条离线命令可复现固定 pin 的好、坏和缺证据对照；
两个原生集成都有明确的能力矩阵；至少 30 例逐项公开来源、预期与实际结果；
在所声明的有限良性回归集上没有误拒；未执行、缺证据、unsupported 和 error
均不算成功检出。每项门槛通过前，README 保持未发布状态。

必须同时报告：已知坏例的误通过数 / 可判定坏例数，已知好例的误拒数 /
可判定好例数，以及声明用例总数、实际执行数、unsupported、缺证据、error、
not_run 的完整分母。缺陷家族、来源和版本分开汇总。客户端崩溃或 exit 1
不是检测到语义违规的充分证据，要检查原生判定的具体检查项与原因。

近期交付按以下顺序推进，工时随实际环境记录，不承诺未知的个人日程：

1. **第一开发批次：**把 MCP 已有实验整理为一个可运行的适配入口，固定原生
   检查项和正反对照，并保留独立的预期，不复制评分逻辑。
2. **第二开发批次：**接入 OWASP 原生判定，按已公开的 #210 / #211 比较原版与
   修复分支，补齐 30 例及证据缺失处理；与 evalmut 在重叠子集上作同预算对照。
3. **首版发布前：**完成离线复现、许可证归属和回归检查，发布带实际可运行
   产物的仓库版本，寻求实际维护者试用。维护者是否采用尚无证据，不能写成
   已验证的市场需求。

v0.2 再考虑至少一类契约在两个独立原生实现中的迁移、真实终态快照适配与
按缺陷机制留出的验证集。v0.1 的人工回归用例不作为盲测泛化结果。

## 选题评分和风险

按研究选题评分技能的 1–5 标准，当前新颖性 **2**、可行性 **4**、可证伪
评估 **4**、机器人直接相关性 **1**、顶会论文成熟度 **2**。这是对当前证据的
判断，不能把“能实现”当作论文贡献。项目决定为 **keep：以聚焦的开源工程
项目推进**，研究主张随证据增长。

三个主要风险是：已有工具覆盖全部目标、原生证据无法支持跨实现迁移、维护者
不愿增加集成负担。对应措施分别是同案例对比、显式报告能力边界、优先提交
低负担的上游回归贡献。若没有新增覆盖和实际复用，缩减自研引擎与功能，
保留已经有用的案例包和上游维护工作。

更强模型带来更多自动生成的工具调用与代码，是本项目值得研究的背景判断；
真正的长期资产应是持续维护的真实回归、可核验来源和低成本原生集成。
这不构成对未来不可替代性、研究录用或 OpenAI 计划入选的保证。
