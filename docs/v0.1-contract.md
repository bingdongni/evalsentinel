# v0.1: native OWASP integration and 30 named controls

This delivery completes the selected two-adapter scope. It keeps the eight MCP
controls and adds 22 distinct OWASP controls; repeating versions or revisions
does not increase the unique-control count.

The OWASP baseline is `970158c10b7e36ae00f12de4ba2a41ca61acabca`; the candidate is
`4af47abb5d31b3cd46867b121d89ce316ab81b42`, the unmerged upstream fix in
[PR #211](https://github.com/OWASP/Agent-Security-Regression-Harness/pull/211).
Expected contract labels are declared before execution. Characterized native
results are recorded separately: a known baseline false acceptance remains
`false_accept` even when reproducing it is an expected regression observation.
The single-use policy comes from upstream issue #210 and PR #211, not a claim
that the baseline's documented MVP policy already required it.

This is an engineering regression set, not a blind preregistered benchmark.
During the initial probe, two positive inputs used unsupported `id` fields;
they were corrected to native-supported `call_id` without changing expected
labels. The original fixture digest and correction are recorded in the corpus.

Each revision runs in its own Python process, imports the original native
scenario validator, Trace loader and assertion, and preserves native results
and exceptions. The project does not port those implementations. Python socket
connections are denied in the OWASP worker; no real tool action is executed.

Commands:

```sh
evalsentinel cases --adapter all
evalsentinel audit owasp --checkout BASE --revision baseline --output-dir runs/base
evalsentinel audit owasp --checkout FIX --revision candidate --require-sound --output-dir runs/fix
evalsentinel audit all --mcp-checkout MCP --owasp-baseline BASE --owasp-candidate FIX --output-dir runs/full
```

The full matrix has 30 named controls and 60 native observation rows:
8 MCP × 2 protocol versions, plus 22 OWASP × 2 revisions. OWASP batches are two
processes, not 44 separate processes. Reports retain invocation/validation
stages so an input-loader error is not represented as an assertion invocation.

The two missing-evidence controls ask for event chronology and durable terminal
state, which the reviewed native Trace cannot establish. They are
`unsupported`, not native grader bugs. One malformed-input control intentionally
raises native TraceValidationError; it remains `error` and never counts as a
semantic catch. The no-action control remains `not_run`.

Default exit 0 means all declared characterization expectations match. It is
not a certificate that a known-broken baseline is sound. `--require-sound`
additionally rejects false accepts, false rejects and unexercised/error results
on adjudicable good/bad controls. Unsupported properties remain outside that
gate and are explicitly listed. Existing MCP CLI behavior remains supported.
