# Changelog

## 0.4.0a1 — 2026-11-13

- Added opt-in `service-tools-v1` with caller-required names and a complete,
  bounded native tool-catalog traversal. Empty pages/cursors remain valid;
  incomplete execution cannot establish missing-tool violations.
- Integrated the unchanged official DBHub 1.6.1 npm release using a locked
  runtime and local read-only SQLite. Native positive/negative SQL assertions,
  eight proxy interventions and remaining functional blind spots are explicit.
- Added installed-wheel real-service controls to Windows/Linux CI. Existing
  caching/coverage contracts and the 30-control corpus remain unchanged.
- No model API calls or GPU; no new original DBHub defect is claimed.

## 0.3.0a1 — 2026-11-12

- Added explicit production/strict caching profiles over the unchanged native
  MCP 2026-07-28 CLI, with native discovery, scope and coverage preserved apart
  from original verdicts. This reproduces the known #516 behavior.
- Added `check mcp-report` with caller-required semantic check IDs. Wire-only,
  all-skipped or missing required evidence cannot pass.
- Added eight caching fixture modes, eleven profile observations, native
  all-skipped/exercised artifact controls, installed-wheel Windows/Linux CI,
  and integration instructions. No model API calls or GPU are required.

## 0.2.0a1 — 2026-11-12

- Added a maintainer-selected OWASP commit gate for the explicit
  `single-use-approval-v1` contract, with blocking semantic/error exits and
  concise control-level diagnostics.
- Verified source hashes before, inside and after the native worker. A fresh
  bytecode-cache prefix prevents stale cached code from masking source changes.
- Added isolated committed native fault controls and post-experiment healthy
  replay to Windows/Linux CI. Incomplete native workers propagate incomplete
  status through full-suite reports.

- Added an opt-in GitHub Actions native demo, reproducible trial instructions and
  a short feedback form. The demo retains its JSON reports for three days and
  makes no model API calls.

- Added strict gating with a real baseline exit 1 and candidate exit 0, offline

- Added evidence-capability boundaries, attributed fixture data, contribution
